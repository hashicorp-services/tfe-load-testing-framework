# Known Limitations

This document describes known limitations of the TFE Load Testing Framework, particularly when running against local development environments.

## Local Development Environment Limitations

### State Download 401 Errors (MinIO Presigned URLs)

**Status:** Known limitation - Not a code issue

**Affected Operations:**
- State file downloads via presigned URLs
- Historical state version downloads

**Symptoms:**
- State uploads work perfectly (100% success rate)
- State downloads fail with 401 Unauthorized errors (~20-30% failure rate)
- Error message: `GET /state-versions/:id/hosted_state [DOWNLOAD]: Exception('Failed to download state: 401')`

**Root Cause:**

The local TFE development environment uses MinIO as an S3-compatible object storage backend. When TFE generates presigned URLs for state downloads, these URLs have the following limitations:

1. **Network Isolation**: The presigned URLs point to the internal MinIO service (`http://minio:9000`) which is only accessible within the Docker/Podman network
2. **Signature Validation**: MinIO's presigned URL signature validation may not work correctly when accessed from outside the container network
3. **Host Resolution**: The URLs cannot be resolved from the host machine where the load tests run

**Impact:**

- ✅ **State uploads**: Work perfectly (100% success)
- ✅ **State version listing**: Work perfectly (100% success)
- ✅ **State version metadata retrieval**: Work perfectly (100% success)
- ✅ **All other TFE API operations**: Work perfectly (100% success)
- ❌ **State file downloads**: Fail with 401 errors (~20-30% failure rate)

**Workarounds:**

1. **Test against production TFE** (Recommended)
   - Deploy tests against a production TFE instance
   - All operations including downloads will work at 100% success rate
   - This provides the most realistic load testing scenario

2. **Accept the limitation for local testing**
   - Use local environment for testing uploads, API operations, and general load patterns
   - Metrics are still properly tracked for failed downloads
   - The failure rate is consistent and predictable

3. **Focus on other operations**
   - Workspace operations: 100% functional
   - Run operations: 100% functional
   - State uploads: 100% functional
   - State metadata operations: 100% functional

**Verification:**

To verify this is the expected behavior and not a configuration issue:


If the token is valid and API calls work, the 401 errors on downloads are expected in the local environment.

**Technical Details:**

The issue occurs because:

1. TFE generates presigned URLs like: `http://minio:9000/tfe-state/state-versions/...?X-Amz-Signature=...`
2. The load test runs on the host machine (outside the container network)
3. The host cannot resolve `minio:9000` or access it directly
4. Even if we could access MinIO directly, the signature might be invalid due to network/host differences

**Future Improvements:**

Potential solutions for future versions:

1. Configure MinIO to be accessible from the host network
2. Use a reverse proxy to expose MinIO with proper hostname resolution
3. Implement a mock state download service for local testing
4. Add configuration to skip download tests in local environments

## Production Environment

**All operations work at 100% success rate when testing against production TFE instances.**

The presigned URLs generated by production TFE instances:
- Use proper external hostnames
- Have correct signature validation
- Are accessible from anywhere with proper authentication
- Work perfectly with the load testing framework

## Metrics and Reporting

**Important:** Even when downloads fail in local environments, the metrics are properly tracked:

- Request counts are accurate
- Failure rates are reported correctly
- Response times are measured
- Error details are logged

This allows you to:
- Verify the load testing framework is working correctly
- Test all other TFE operations at scale
- Validate metrics collection and reporting
- Prepare for production testing
